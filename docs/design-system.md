

# Veekay Labs
## Design System

---

# Purpose

This document defines the visual language, interaction principles, and reusable UI components for Veekay Labs. The goal is to create a modern AI-native experience that feels professional, calm, and focused while reinforcing the brand identity.

---

# Design Principles

## Clarity First
Every page should communicate one primary idea before introducing supporting details.

## Minimal by Default
Use generous whitespace, simple layouts, and avoid unnecessary visual clutter.

## Progressive Disclosure
Surface summaries first and allow users to expand into technical details only when they choose.

## Story Before Specifications
Lead with the problem, impact, and outcomes before presenting technical implementation.

## Consistency
Every page should share the same spacing, typography, component behavior, and interaction patterns.

---

# Brand Personality

The interface should feel:

- Professional
- Modern
- Intelligent
- Calm
- Trustworthy
- Technical without being overwhelming
- Product-focused rather than résumé-focused

Inspired by the design philosophy of Stripe, Linear, Vercel, Anthropic, Notion, and OpenAI.

---

# Color Palette

## Primary
- Navy Blue — Primary brand color
- Cyan Gradient — Accent and interactive highlights
- White — Primary background

## Neutral
- Slate 900 — Primary text
- Slate 700 — Secondary text
- Slate 300 — Borders
- Slate 100 — Cards and subtle backgrounds

## Semantic
- Success — Green
- Warning — Amber
- Error — Red
- Info — Blue

Gradients should be subtle and used sparingly for hero sections and primary CTAs.

---

# Typography

## Headings
- Large, bold, high contrast
- Short and impactful

## Body
- Comfortable reading width
- Clear hierarchy
- Optimized for long-form content

## Code
- Monospace font for prompts, commands, and architecture snippets.

---

# Layout

- 12-column responsive grid
- Maximum content width around 1200px
- Generous vertical spacing
- Mobile-first responsive behavior

---

# Component Library

## Navigation
Sticky navigation with simple labels.

## Hero
Headline, supporting copy, primary CTAs, subtle background animation.

## Cards
Reusable cards for projects, articles, frameworks, and demos.

## Metrics
Animated impact counters.

## Timeline
Career journey and roadmap visualization.

## Tabs
Used for project sections such as Overview, Architecture, Demo, Evaluation, GitHub, Lessons Learned.

## Accordions
Used for Deep Dive sections and FAQs.

## Progress Bars
Used in Now Building, roadmap, and project status.

## AI Chat Panel
Reusable conversational interface for Ask AI.

---

# Icons

Use a consistent outline icon style.

Icons should communicate meaning without dominating the interface.

---

# Motion

Animations should be subtle and purposeful.

- Smooth page transitions
- Fade-in sections
- Card hover effects
- Progress animations
- Respect reduced-motion accessibility preferences

---

# Accessibility

- WCAG 2.1 AA target
- Keyboard navigation
- High color contrast
- Screen reader friendly
- Visible focus states

---

# Responsive Design

Support:
- Mobile
- Tablet
- Desktop
- Large monitors

Navigation should collapse gracefully on smaller screens while preserving access to Ask AI.

---

# Theme Support

Initial release:
- Light mode

Future:
- Dark mode
- User-selectable themes

---

# Reusable Page Pattern

Every major page should follow this structure:

1. Hero
2. Overview
3. Primary Content
4. Related Resources
5. Deep Dive
6. Call to Action

---

# Design Checklist

Before publishing any page, verify:

- Clear primary purpose
- Consistent typography
- Consistent spacing
- Responsive layout
- Accessible interactions
- Appropriate CTA
- Related content links
- AI Assistant entry point available
